# Ink Studio · 传图、卡片与 OTA

[打开 Ink Studio](https://kxxxxc.github.io/ink-studio/)

浏览器里的墨水屏工具，顶部四个页签：

- **传图工具**：排版图片、文字与手写图层，转换为墨水屏位图，并通过 Web Bluetooth 直传价签。
- **模式卡片**：月历、日历 + 天气、五天天气、倒计时、每日一言，直接推到 800 × 480 黑白红价签。
- **字模**：选本机字体，在浏览器里栅格化成 1 bit 字模，打成 FNT1 字库，再通过 BLE 写进价签的 U5。
- **OTA 工具**：选择 `.eslfw` 固件包，在本地校验 CRC32 / SHA-256 / ECDSA P-256 签名，再通过 BLE 写入价签备用槽。

可直接打开 `index.html` 离线编辑和导出。蓝牙与 OTA 需要通过 HTTPS 或 localhost，在桌面 Chrome / Edge 或 Android Chrome 中打开。图片处理、验签和卡片数据组装都在本地完成。

## 这个目录也是 prism-ble 网页的唯一真源

`prism-ble`（ESP32-C3 网关，页面经 HTTP 中转 BLE，走不了 Web Bluetooth）不复制这里的文件，
而是在编译时直接读过去拼装。分三层：

| 层 | 文件 | 谁维护 |
|---|---|---|
| 公共 | `core.js` `panels.js` `app.js` `cards.js` `ota-core.js` `ota.js` `fontpack.js` `fonts.js` `tabs.js` `bwr.css` | 这里，**两边同时生效** |
| 外壳 | `index.html` | 这里，prism-ble 的 `studio.html` 由它生成 |
| 传输 | `ble-transfer.js`（直连 GATT） | 这里；网关那份在 `prism-ble/main/web/c3/c3-transfer.js` |

协议点只有两个，改的时候要留意对端：

- `window.INK_BLE`：页面与传输层的契约，`ble-transfer.js` 和 `c3-transfer.js` 各实现一份，接口必须一致。
- `window.OTA_VERIFIER`：可选钩子。不设置时 `ota.js` 用 WebCrypto 本地验签；网关页设成转发给本板。

`tabs.js` 的页签列表读 `<body data-tabs="image,cards,fonts,ota">`，缺省就是这四个；网关页多一个
`advanced`，写在它自己的外壳里。改 UI 文案只改这里，`prism-ble/main/web/c3/shell_rules.py` 里
对不上的规则会让固件构建失败，不会悄悄漂移。

## 编辑与导出

1. 选择屏幕型号与色彩模式。列表包含 Waveshare Arduino 示例目录里的 35 个型号、43 个面板×色彩组合，支持黑白、黑白红、黑白黄、四灰阶和七色。也可按面板设置自定义画布。旁边的「横版 / 竖版」按钮切换编辑方向（默认横版）：切到竖版时画布宽高对调，已有图层整体旋转 90° 且缩放保持不变，画面观感不变。
2. 点击画布、拖放或粘贴图片。第一张图片等比铺满画布，拖动可调整取景。缩放用滚轮或双指手势（不占滑杆）；「旋转」滑块和预设、抖动、映射、适配在同一行，三指手势也能旋转图层。「适配」可切换铺满或完整显示。
3. 「＋ 图层」可添加图片、文字和手写。只有一层时直接使用工具栏，多层时在图层列表里选择、排序或隐藏。选中可见手写层即可落笔，切走即退出。三种图层均可擦除与撤销擦除，露出下方图层或白底。
4. 每层独立设置抖动与色彩映射。图片自动选择转换参数，文字和手写默认关闭抖动。黑白红或黑白黄模式下，「自动主色」按该层可见像素的 RGB 主通道占比选择红墨或黄墨的来源。也可指定 RGB 通道，或用「指定源色」将接近所选色相的像素映射到该墨色。
5. 「预设」在主界面。点「手动模式」可查看选中图片层的 RGB 与亮度直方图，调整亮度、对比度和阈值。拖动直方图上的阈值线也可调阈值。「恢复自动」重算当前层。
6. 可导出原分辨率 PNG。手动模式另有平面 PNG、BIN 和参数 JSON。**导出与 BLE 传图始终是横版**：竖版编辑时成品会顺时针旋转 90° 并按屏幕型号的宽高输出；状态栏和导出区同时显示编辑尺寸和成品尺寸，参数 JSON 里记录方向和旋转方式。

自动转换参考 [EPD Optimize](https://github.com/paperlesspaper/epdoptimize)。

## 位图格式

从左上角开始逐行排列。每行第一像素占最高位，末尾不足一字节补 0。每平面长度为 `ceil(width × bitsPerPixel / 8) × height`。双平面 BIN 依次拼接平面 1 和 2。

| 模式 | 位数与平面 | 像素编码 |
| --- | --- | --- |
| 黑白 | 1 bit，单平面 | 黑 0、白 1 |
| 黑白红或黑白黄 | 每像素每平面 1 bit，双平面 | 依次为黑白平面和红/黄平面。黑 `(0,0)`、白 `(1,0)`、红/黄在驱动编码为 `(1,1)`，网关编码为 `(0,1)` |
| 四灰阶 | 2 bit，单平面 | 黑 `00`、深灰 `01`、浅灰 `10`、白 `11` |
| 七色 | 4 bit，单平面 | `0–6` 依次为黑、白、绿、蓝、红、黄、橙 |

BLE 固定使用驱动编码及表中的原始极性。手动模式里的网关编码和取反设置用于文件导出。文件面板显示 CRC16-CCITT-FALSE（初值 `0xFFFF`，多项式 `0x1021`）。BLE 使用 CRC32/ISO-HDLC（反射多项式 `0xEDB88320`，初值与最终异或均为 `0xFFFFFFFF`，`123456789` 的结果为 `0xCBF43926`）。

屏幕列表定义的是成品（横版）尺寸和调色板；竖版只是编辑时的临时方向，不会改变发给设备的宽高。设备端驱动按具体型号处理旋转、控制器极性、位平面拆分及刷新时序。

## BLE 设备接入

TLSR8359 价签固件 **0.6.2** 支持无配对、无密钥的 BLE 图传、卡片与 OTA。0.5.81 起删除了 16 B 应用密钥、SMP 配对和 `0x06–0x0A`；固件真实性只由 `0x22` 的 ECDSA 签名和 `0x20` 的 `seq` 防降级保证。第三方设备可实现下述协议。

### 广播、GATT 和屏幕规格

- 广播名以 `ESL-` 开头，或在广播中公布服务 UUID `A000`，浏览器才会列出设备。
- 服务 `A000` 下，`A001` 支持 Write 和 Write Without Response，图传允许明文写入。`A002` 支持 Notify，允许在未配对时订阅。完整 UUID 采用 `0000xxxx-0000-1000-8000-00805f9b34fb`。浏览器先订阅，再发送命令。若状态查询的通知超时，网页在当前连接上重试一次。
- 所有设备均使用下表的 13 字节版本 1 状态通知。模式 `01–05` 依次为黑白、黑白红、黑白黄、四灰阶、七色。宽高各为 8–1024。发送前网页会重新读取状态，要求画布宽、高和色彩模式均匹配。

例如，空闲的 400 × 300 黑白设备收到 `17` 后回复 `97 00 00 00 00 00 00 01 90 01 2C 01 01`。每次传输仅有平面 1，长度为 15,000 B。800 × 480 黑白红价签的空闲回执为 `97 00 00 00 00 00 00 01 20 03 E0 01 02`，平面 1 和 2 各为 48,000 B。

### 数据帧

下表首字节为十六进制命令或回执。未标注宽度的字段为 1 字节。传图命令均使用有响应写入。协议回执均经 A002 通知，`rc=00` 表示成功。

| A001 写入 | A002 通知 | 用途 |
| --- | --- | --- |
| `17` | `97 active loaded got:u32LE 01 width:u16LE height:u16LE mode:u8` | `active` 为接收中的平面，`loaded` 为已提交的平面，`00` 表示无。平面从 1 开始 |
| `18 token` | `98 token mtu received_len` | 回显 token，报告协商后的 ATT MTU（23–255）和请求长度 2 |
| `10 plane length:u32LE crc32:u32LE` | `90 rc erase_ms:u16BE` | 开始接收一个平面，长度和 CRC 针对整个平面 |
| `11 payload…` | 每累计 4096 B 通知 `91 got:u32LE` | 单包数据上限 `min(243, MTU−4)`。每包使用 GATT 带响应写入，等待 ATT 确认后再发下一包。`91` 是进度通知，丢失时仍可继续传输 |
| `12` | `92 rc got:u32LE crc32:u32LE write_ms:u16BE erase_ms:u16BE` | 提交并从存储读回，返回实际数据长度和 CRC32 |
| `13 plane` | `93 rc ms:u16BE` | 把已校验平面写入面板 RAM |
| `14` | 先 `94 00`，完成时 `94 status busy_ms:u16BE total_ms:u16BE` | 全屏刷新，完成 `status=01`，失败使用大于 1 的状态；总耗时用非零毫秒数 |
| `15` | `95 rc` | 中止并清理未完成传输 |
| 任意命令错误 | `8F code` | 通用错误回执 |

顺序为查状态、查 MTU、逐平面执行 `10 → 11… → 12 → 13`，最后执行 `14`。存储读回失败或 CRC 不符时，网页停止发送，不会要求刷新。价签下拉框固定在页面右上角：点「扫描」用浏览器设备选择器添加价签，选择本身不建立连接；每次传输临时连接、结束自动断开。若设备报告正在接收的平面，可以先用「中止未完成传输」（也会临时连接）。收到刷屏完成通知后自动断开。全刷完成通知的等待上限是 40 秒，若完成前断开，网页提示到屏幕上确认结果。

## 价签卡片

在「模式卡片」页签选择月历、日历 + 天气、五天天气、倒计时或每日一言。TLSR8359 0.6.2 的 800 × 480 黑白红价签可以直接使用这五种版式。页面与传图、OTA 共用右上角的价签选择和按需 BLE 会话，无需网关或密钥。配置保存在当前浏览器内。

- 月历可选择周日或周一开始，并从 [holiday-cn](https://github.com/NateScarlet/holiday-cn) 同步中国大陆调休。天气卡片支持搜索城市或填写坐标，在浏览器里从 [Open-Meteo](https://open-meteo.com/) 获取数据。天气随推送更新。七天完整天气帧需要 ATT MTU 至少 146。网关版（prism-ble 五页签）默认沿用「高级设置」里的城市/坐标，卡片页改动会同步回网关；独立版仍只用浏览器本地配置。
- 倒计时填写标题、日期和可选正文。每日一言可手动填 1–255 条（整包 ≤ 16 KB），或取示例及 [一言](https://hitokoto.cn/) 数据。价签按同步时的本机日期计算倒计时，按日切换缓存的一言。可以读取当前卡片状态和手动切换到下一条。
- 卡片由价签绘制，整刷约 25 秒，蓝牙可能断开。页面在请求刷新前核对价签回执及卡片状态，一言还会校验 Flash 回读。刷新受理回执表示价签已接收请求。屏上结果可直接查看，之后点「读价签状态」会临时连接并读取上次整刷的准备/波形耗时。0.6.x 会缓存已绘制卡片的指纹，传图后重推相同卡片有可能跳过刷屏。

### 卡片数据帧

卡片与图片使用同一 GATT 服务。下表帧首为十六进制命令或回执，未标宽度的字段占 1 字节。每个有回执的配置命令完成后再继续。只有 `45` 使用无响应写入。

| A001 写入 | A002 通知 | 用途 |
| --- | --- | --- |
| `37 year:u16LE month day hour minute` | `B7 ok` | 同步本机日期和时间 |
| `40 year:u16LE count` | `C0 ok` | 开始同步调休日历，最多 64 条 |
| `41 [month day kind]…` | — | 按 MTU 分包，`kind=01` 休、`02` 班 |
| `42` | `C2 count` | 读回调休条数 |
| `43 n [day]… current hourly` | `C3 ok` | 每日条目共 `n` 条（至多 7），随后为当前天气和 24 小时预报 |
| `44 mode week accent len city…` | `C4 ok` | 设置版式（`01` 至 `05` 按上述顺序）、每周起点（`00` 周日、`01` 周一）和城市（UTF-8，至多 11 B）。网页保留默认 `accent=00` |
| `45` | `C5 00 repaint` | 启动刷屏，`repaint=00` 表示按卡片指纹跳过刷屏，`01` 表示开始整刷 |
| `46` | `C6 mode assets days rest flags busy:u16BE clock month day quotes slot extra pre_ms:u16BE total_ms:u16BE` | 读状态，opcode 加 17 B，共 18 B。前 13 个 payload 字节保持旧布局；末尾新增准备耗时和总耗时。`flags` bit0/1 表示逐时/当前天气，bit2 表示周一起始。`clock` bit0 表示时间已同步，`extra` bit0 表示倒计时已设置、bit2 表示已加载 U5 字库。`slot` 从 0 开始 |
| `50 year:u16LE month day tlen title… blen body…` | `D0 ok missing_title missing_body` | UTF-8 标题 1–47 B，正文至多 119 B，回执含缺字数 |
| `51 count len:u16LE crc32:u32LE` | `D1 ok count` | 开始接收一言整包，1–255 条，整包 ≤ 16384 B |
| `52 payload…` | 每累计经过 512 B 边界时 `D2 got:u16BE` | 按 MTU 分包，以 ATT 响应为每包的节流依据 |
| `53` | `D3 rc got:u16BE count` | 提交并回读一言。`rc=00` 成功，01 未开始，02 长度不足，03 CRC 不匹配，04 格式错误，05 Flash 回读不一致 |
| `54` | `D4 count slot` | 切到下一条一言，随后用 `45` 刷屏 |
| `58` | `D8 count slot used:u16LE gen:u16LE` | 只读：一言库条数、当前 slot、已用字节和代号。旧页面不调用它也不影响推送 |

配置回执的 `ok=01` 表示接受。一言整包是 ASCII `QT01`、条数、一个 `00` 保留字节，再依次写 `正文长度 正文 出处长度 出处`，长度按 UTF-8 字节计，正文 1–223 B，出处 0–39 B。CRC32 覆盖整包。

`43` 每日字段为 `天气码 最高温 最低温 夜间天气码 降水概率 日出时 日出分 日落时 日落分 AQI 风向 风力`。当前字段为 `天气码 温度 体感温度 湿度 气压:u16LE 降水概率 风向 风力`。逐时预报每小时写 `温度 降水概率`，顺序为本机时间的 0–23 时。温度为 `i8` 摄氏度，概率和湿度为 0–100，气压单位 hPa。风向 `0–7` 由北顺时针，`255` 为未知。天气码 `0–15` 依次为晴、多云、阴、小雨、中雨、大雨、雷阵雨、小雪、中雪、大雪、雨夹雪、雾、霾、沙尘、大风、未知。

## OTA 工具

「OTA 工具」页签直接通过 Web Bluetooth 升级价签，不需要网关。流程是：

1. 在右上角选价签，点「读取 OTA 状态」（临时连接、读完断开），确认在跑槽的 `seq`。
2. 选择 `.eslfw`。页面先校验 magic、长度、CRC32、SHA-256 和 ECDSA P-256 签名，再比较 `seq`。
3. 按 `0x20 → 0x21… → 0x22` 写入备用槽；`0x22` 的 98 B 帧要求 ATT MTU 至少 101。
4. 价签回读 Flash、验签、保存回滚副本、切槽并自动重启。
5. 价签重启后再读一次 `0x23`，确认 `seq_active` 已变成新包的 seq。

### OTA 数据帧

| A001 写入 | A002 通知 | 用途 |
| --- | --- | --- |
| `20 len:u32LE crc32:u32LE seq:u32LE` | `A0 rc erase_ms:u16BE got:u32LE` | 打开或续传；`got>0` 表示从该偏移继续 |
| `21 payload…` | 每 4 KiB `A1 got:u32LE` | 写入备用槽，无偏移字段 |
| `22 sha256:32 sig:64 [key_id]` | `A2 rc copy_ms:u16BE` | 校验、搬槽、武装切换并重启 |
| `23` | `A3` + 26 B | 状态：open/slot/pending/tries/got/len/crc/seq/seq_active/rb_valid/rb_slot |
| `24` | `A4 rc` | 放弃未完成传输 |
| `2F` | `A6 mask ms:u16BE sha256("abc")[0..7]` | 密码学自检，`mask & 0x0F == 0x0F` 为健康 |

错误码：`20` 状态错、`21` 参数、`22` 长度、`23` 降级被拒、`24` 字节不足、`25` Flash 内容不符、`26` SHA-256 不符、`27` 签名不符、`28` 搬运失败、`29` 无回滚副本、`2A` 镜像布局不符。

`.eslfw` 是 116 B 头加镜像原文：

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 4 | `ESLF` |
| 4 | 1 | manifest 版本 = 1 |
| 5 | 1 | key id（0 或 1） |
| 6 | 2 | 保留 |
| 8 | 4 | 镜像长度，u32LE |
| 12 | 4 | 镜像 CRC32，u32LE |
| 16 | 4 | seq，u32LE |
| 20 | 32 | SHA-256(image) |
| 52 | 64 | ECDSA P-256 签名，r‖s 各 32 B 大端 |
| 116 | n | 镜像原文 |

签名覆盖 `SHA-256(bytes[0, 52))`。公钥固定在 `ota-core.js`，与固件 `src/ota_pubkey.h` / `src/ota_pubkey1.h` 对应；私钥只在电脑上，不进网页。

## 字模 · 在浏览器里造字库

价签的汉字来自 U5（第二颗 NOR）上的一份 FNT1 字库，只在开机时加载一次。这个页签把「造包」搬进了
浏览器：字形来自本机字体，栅格化用 canvas，打包和校验用 `fontpack.js`（纯逻辑，Node 可测）。

1. **选字体**。「仿宋 / 楷体 / 宋体 / 黑体 / 微软雅黑 / 等线 / 思源黑体 / 思源宋体 / 隶书 / 幼圆」
   按 Windows、macOS、Android 的命名各试一遍，装了的排在前面的分组里；没装的分到「未安装」。
   也可以「载入字体文件…」直接丢一个 `.ttf/.otf/.woff2` 进去（`.ttc` 字体集一般不行）。
   判定方式是「画一个汉字再逐像素比」，所以 `document.fonts.check()` 那种误判不会落到包里。
2. **选覆盖（只能选预设）**。四档，下拉框里直接写着现算出来的体积：
   | 预设 | 体积 |
   |---|---|
   | 仅 16 px 一级 | 135.6 KB |
   | 仅 16 px 一二级 | 235.5 KB |
   | **16 px 一二级 + 24 px 一级**（默认） | **532.4 KB** |
   | 16 px 一二级 + 24 px 一二级 | 749.7 KB |
   16 px / 24 px 不再单独挑，半角 ASCII 与标点符号跟着字号一起进包。默认那档就是固件默认的
   `gb24l1`：24 px 缺的二级汉字由固件把 16 px 按 3/2 放大补上，不会出方块。
3. **看预览**。预览就是价签上的字模：格子边框画出来，格子里的每个小方点是一个像素，格子下面标着
   这个字占了格子的百分之几。滑块 2×–10× 放大，方便数笔画。「加粗」不是预览特效 —— 它把笔画
   统一加宽 1 px 并真的写进字库（16 px 上容易糊，先看预览）。
4. **生成**。4 倍超采样后降采样：16 px 仿宋的竖笔只有约 0.65 px 粗，直接阈值化会被切成虚线，
   4×4 子像素相或之后才还原成 1 px。字体里没有的字**直接丢掉**，让固件走回退，而不是塞一个方框。
5. **写入 U5**。`0x47` 流式写入 + 提交时逐页回读比对；包先过 `fontpack.verify()`（目录 CRC、
   索引有序、地址与包尾），有一条不对就不让发。写完**必须断电重启价签**，字库只在开机那一次加载。

浏览器生成的包与 `tools/tag_assets/pack_fullfont.py` 的差别只有两点：CLI 的 `gb24l1` 多带 3 个
「卡片白名单」汉字（+222 B，网页端让它们走 16 px 放大），以及抗锯齿算法不同（canvas 比 PIL/FreeType
略粗）。长度、区间、索引、CRC 的规则完全一致 —— `test-fonts.js` 会拿 CLI 真打出来的包逐字段对拍。

字库区就是 U5 上 `0x022000` 起的 **750 KiB**（768 000 B），最大那档 749.7 KB 正好装下（余 268 B）。
基址在固件的 `render.h: FNT_ADDR`，上限在 `fontpack.js: FONT_MAX` / `pack_fullfont.py: U5_FONT_END`，
`test-fonts.js` 有一条防漂移测试盯着这三处。再往上（`0x0DE000` 之后）没分配，以后要更大的字库再划。

## 部署与自动同步

本地源在 `tools/bwr-studio`，线上在 [GitHub 仓库](https://github.com/kxxxxc/ink-studio) 的 `new-branch` 根目录，由 GitHub Pages 直接发布，`.nojekyll` 使文件按原样上站。

Gitee 只作为源码仓库。GitHub Actions 工作流 `.github/workflows/ink-studio-sync.yml` 每 15 分钟从 Gitee `master` 的 `tools/bwr-studio` 稀疏检出站点文件，内容有变化就提交到 `new-branch`，Pages 随后自动重建。也可以在 GitHub 的 Actions 页手动 `Run workflow`。

首次启用需要在 GitHub 仓库添加一个 Secret：

1. 在 Gitee「设置 → 私人令牌」创建一个带 `project` 权限的令牌。
2. 在 GitHub 仓库「Settings → Secrets and variables → Actions」新建 `GITEE_TOKEN`，值是上一步的令牌。用户名默认 `kang-chao`，需要覆盖时再加 `GITEE_USER`。
3. 手动跑一次 `Sync Ink Studio from Gitee`。没有配置 `GITEE_TOKEN` 时工作流只打印一条 notice 并跳过，不会失败。

同步记录在 GitHub Actions 的 `Sync Ink Studio from Gitee` 里；如果拉取失败，先检查 `GITEE_TOKEN` 是否过期。提交到 Gitee 后通常 5–15 分钟内上站。

如果更希望“Gitee 主动推 GitHub”，Gitee 仓库设置里有「仓库镜像管理 → Push 方向镜像」，它按整仓镜像，适合再建一个完整镜像仓库；本 Pages 仓库只放站点文件，因此这里采用定时拉取 `tools/bwr-studio` 的方式。

部署文件共 13 个：

`index.html`、`bwr.css`、`core.js`、`panels.js`、`app.js`、`ble-transfer.js`、`cards.js`、`ota-core.js`、`ota.js`、`fontpack.js`、`fonts.js`、`tabs.js`、`.nojekyll`。

手动复制部署时保留这些文件即可；`README.md`、`preview.png`、`start.cmd` 不参与站点运行。

## 验证

在网页地址后加 `?fresh=1&selftest=1` 可运行浏览器自测，结果显示在页面底部。主工程另有：

```powershell
node tools/bwr-studio/test-core.js       # 图像算法
node tools/bwr-studio/test-fonts.js      # FNT1 编解码、GB2312 字表、四档预设、0x47 帧、U5 地址防漂移
node tools/bwr-studio/test-fonts-browser.js   # 真跑一遍浏览器：页签形状 + 预览 + 生成 → 回传字节 → 再校验
```

`test-fonts.js` 20 项、`test-core.js` 21 项。`test-fonts-browser.js` 找不到 Chrome 就打印 SKIP，
可以用 `INK_CHROME=<chrome.exe>` 指定路径；它在 headless Chrome 里检查「只有四档预设、没有 16/24
单独设置、没有 U5 分区表」，量预览的墨迹（加粗变多、放大变高），然后真的生成一份「仅 16 px 一级」
字库（约 136 KB），把字节回传给 Node 再用 `fontpack.verify()` 校验一遍，顺带验模式卡片页的
「追加 7 条一言」不覆盖已有内容 —— 这是唯一能证明「canvas 光栅化 + 打包 + 校验」这条链在真浏览器里成
立的方法。

OTA 可以用 `dist/tlsr8359-ble-0.6.2.eslfw` 手动选择，页面会显示 CRC32、SHA-256、ECDSA 三项校验结果；真机升级前先读一次 OTA 状态，确认在跑槽的 seq。
