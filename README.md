# Ink Studio · 墨水屏传图

[打开 Ink Studio](https://kxxxxc.github.io/ink-studio/)

在浏览器里排版图片、文字与手写图层，并转换为墨水屏位图。可直接打开 `index.html` 离线编辑和导出。蓝牙直传需要通过 HTTPS 或 localhost 在桌面 Chrome / Edge 或 Android Chrome 中打开。图片处理在本地完成。

## 编辑与导出

1. 选择屏幕型号与色彩模式。列表包含 Waveshare Arduino 示例目录里的 31 个型号，支持黑白、黑白红、黑白黄、四灰阶和七色。也可按面板设置自定义画布。
2. 点击画布、拖放或粘贴图片。第一张图片等比铺满画布，拖动可调整取景。滚轮或双指缩放，三指或「旋转」滑块旋转图层。「适配」可切换铺满或完整显示。
3. 「＋ 图层」可添加图片、文字和手写。只有一层时直接使用工具栏，多层时在图层列表里选择、排序或隐藏。选中可见手写层即可落笔，切走即退出。三种图层均可擦除与撤销擦除，露出下方图层或白底。
4. 每层独立设置抖动与色彩映射。图片自动选择转换参数，文字和手写默认关闭抖动。黑白红或黑白黄模式下，「自动主色」按该层可见像素的 RGB 主通道占比选择红墨或黄墨的来源。也可指定 RGB 通道，或用「指定源色」将接近所选色相的像素映射到该墨色。
5. 「预设」在主界面。点「手动模式」可查看选中图片层的 RGB 与亮度直方图，调整亮度、对比度和阈值。拖动直方图上的阈值线也可调阈值。「恢复自动」重算当前层。
6. 可导出原分辨率 PNG。手动模式另有平面 PNG、BIN 和参数 JSON。

自动转换参考 [EPD Optimize](https://github.com/paperlesspaper/epdoptimize)。

## 位图格式

从左上角开始逐行排列。每行第一像素占最高位，末尾不足一字节补 0。每平面长度为 `ceil(width × bitsPerPixel / 8) × height`。双平面 BIN 依次拼接平面 1 和 2。

| 模式 | 位数与平面 | 像素编码 |
| --- | --- | --- |
| 黑白 | 1 bit，单平面 | 黑 0、白 1 |
| 黑白红或黑白黄 | 每像素每平面 1 bit，双平面 | 依次为黑白平面和红/黄平面。黑 `(0,0)`、白 `(1,0)`、红/黄在驱动编码为 `(1,1)`，网关编码为 `(0,1)` |
| 四灰阶 | 2 bit，单平面 | 黑 `00`、深灰 `01`、浅灰 `10`、白 `11` |
| 七色 | 4 bit，单平面 | `0–6` 依次为黑、白、绿、蓝、红、黄、橙 |

BLE 固定使用驱动编码及表中的原始极性。手动模式里的网关编码和取反设置用于文件导出。文件面板显示 CRC16-CCITT-FALSE（初值 `0xFFFF`，多项式 `0x1021`）。BLE 使用 CRC32/ISO-HDLC（反射多项式 `0xEDB88320`，初值与最终异或均为 `0xFFFFFFFF`，`123456789` 的结果为 `0xCBF43926`）。

屏幕列表定义的是画布尺寸和调色板。设备端驱动按具体型号处理旋转、控制器极性、位平面拆分及刷新时序。

## BLE 设备接入

TLSR8359 价签固件 **0.5.78** 的下述传图命令不要求应用层密钥或解锁。A001 写入仍需要 BLE 配对后的加密链路，首次连接按浏览器提示配对。第三方设备可以实现同一协议。

### 广播、GATT 和屏幕规格

- 广播名以 `ESL-` 开头，或在广播中公布服务 UUID `A000`，浏览器才会列出设备。
- 服务 `A000` 下，`A001` 支持 Write 和 Write Without Response，`A002` 支持 Notify。完整 UUID 采用 `0000xxxx-0000-1000-8000-00805f9b34fb`。浏览器先订阅，再发送命令。
- 旧价签的状态通知固定为 7 字节，网页按 **800 × 480 黑白红** 处理（两平面各 48,000 B）。
- 其他画布使用 13 字节版本 1 状态通知。在原有 7 字节后追加 `01 width:u16LE height:u16LE mode:u8`。模式 `01–05` 依次为黑白、黑白红、黑白黄、四灰阶、七色。宽高各为 8–1024。发送前网页会重新读取状态，要求画布宽、高和色彩模式均匹配。

例如，空闲的 400 × 300 黑白设备收到 `17` 后回复 `97 00 00 00 00 00 00 01 90 01 2C 01 01`。每次传输仅有平面 1，长度为 15,000 B。刷新回执和 CRC 与双平面流程相同。

### 数据帧

下表首字节为十六进制命令或回执。未标注宽度的字段为 1 字节。除数据包 `11` 使用无响应写入，其余命令使用有响应写入。协议回执均经 A002 通知，`rc=00` 表示成功。

| A001 写入 | A002 通知 | 用途 |
| --- | --- | --- |
| `17` | `97 active loaded got:u32LE`，版本 1 可追加上述 6 字节 | `active` 为接收中的平面，`loaded` 为已提交的平面，`00` 表示无。平面从 1 开始 |
| `18 token` | `98 token mtu received_len` | 回显 token，报告协商后的 ATT MTU（23–255）和请求长度 2 |
| `10 plane length:u32LE crc32:u32LE` | `90 rc erase_ms:u16BE` | 开始接收一个平面，长度和 CRC 针对整个平面 |
| `11 payload…` | 每累计 4096 B 通知 `91 got:u32LE` | 单包数据上限 `min(243, MTU−4)`。网页在 4096 B 边界停等确认，最后一段完成后直接提交 |
| `12` | `92 rc got:u32LE crc32:u32LE write_ms:u16BE erase_ms:u16BE` | 提交并从存储读回，返回实际数据长度和 CRC32 |
| `13 plane` | `93 rc ms:u16BE` | 把已校验平面写入面板 RAM |
| `14` | 先 `94 00`，完成时 `94 status busy_ms:u16BE total_ms:u16BE` | 全屏刷新，完成 `status=01`，失败使用大于 1 的状态；总耗时用非零毫秒数 |
| `15` | `95 rc` | 中止并清理未完成传输 |
| 任意命令错误 | `8F code` | 通用错误回执 |

顺序为查状态、查 MTU、逐平面执行 `10 → 11… → 12 → 13`，最后执行 `14`。存储读回失败或 CRC 不符时，网页停止发送，不会要求刷新。若设备报告正在接收的平面，可以先用「中止未完成传输」。全刷完成通知的等待上限是 40 秒，若完成前断开，网页提示到屏幕上确认结果。

## 部署与验证

[GitHub 仓库](https://github.com/kxxxxc/ink-studio) 由 Pages 发布 `new-branch` 的根目录，`.nojekyll` 使文件按原样上站。复制部署时保留 `index.html`、`bwr.css`、`core.js`、`panels.js`、`app.js`、`ble-transfer.js` 和 `.nojekyll`。

在网页地址后加 `?fresh=1&selftest=1` 可运行浏览器自测，结果显示在页面底部。主工程另有算法回归 `node tools/bwr-studio/test-core.js` 和网关逐像素对照 `node gateway-idf/tools/web_mix_test.js`。
